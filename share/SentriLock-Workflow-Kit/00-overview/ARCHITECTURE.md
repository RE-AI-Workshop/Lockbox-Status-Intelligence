# Architecture

## Dev pipeline

```
                    ┌─────────────┐
                    │ /intake-agent│  Step 1
                    └──────┬──────┘
                           │ writes active-brief.md
                           ▼
              ┌────────────────────────┐
              │  Workflow extension     │
              │  file watcher + router  │
              └────────────┬───────────┘
                           │
        backend            │           frontend
  /backend-implementation  │     /frontend-implementation
  /unit-test               │     /frontend-unit-test
  /api-suite               │     /frontend-reviewer
  /api-execution           │     /frontend-handoff
  /reviewer                │
  /handoff                 │
                           │
              rework: tests → unit-test
                      code|mixed → implementation
              cap: 5 loops → human
```

Slash aliases (Cursor only): see `03-reference-implementation/ai/cursor-slash-aliases.json`.

## QA pipeline

Separate file: `active-qa-brief.md`. Separate start command. Same extension.

```
/qa-intake → /qa-test-generator → /qa-smoke-builder → /qa-report
```

QA targets a **deployed** API. Dev Steps 2 and 5 target **local** (the branch you just built). Do not collapse those environments.

## Brief protocol (the wire format)

Progress table row examples the parser understands:

```
| 2 — Backend Implementation | ✅ Complete |
| 4 — API Suite Generation   | ⏭️ Skipped |
| 5 — API Suite Execution    | ⛔ Blocked — Code Fix Required |
| 6 — Backend Review         | ⛔ Blocked — Rework Required |
```

Plus:

```
- Ticket ID: DEMO-123
- Rework loops: 1
**Track** | **Backend**
**Rework target:** tests|code|mixed
## Step 2 Summary
```

`✅ Complete` or `⏭️ Skipped` without the matching `## Step N Summary` heading **does not** open the next agent.

Standard ticket IDs such as `DEMO-123` work by default. Projects can enforce a stricter workspace regex; see `02-porting/TICKET-PREFIX.md`.

## Extension internals (what to keep in sync)

| File | Job |
|------|-----|
| `extension/src/briefRouting.ts` | Pure parse + route (unit-tested) |
| `extension/src/promptLaunch.ts` | Cursor slash-chip / Agent mode |
| `extension/src/extension.ts` | Watcher, status bar, commands, debounce |
| `scripts/lib/project-workflow-router.mjs` | Limited notification/manual-open fallback used when the extension cannot be installed |

`briefRouting.ts` is canonical. The CLI fallback does not auto-open chats and does not promise
the extension's full rework, pending-return, or duplicate-chat behavior. If you extend the
fallback, add equivalent tests before describing it as parity.

## Prompt → chat

- **VS Code Copilot:** `workbench.action.chat.open` with `/intake-agent`.
- **Cursor:** create an Agent composer, type a **Plan-safe** slash (`/backend-code` not `/backend-implementation`), accept the picker chip, submit.

Prompt source of truth is always `.github/prompts/*.prompt.md`. Cursor copies are generated by `scripts/generate-cursor-commands.mjs`.
